# Baseline: MediatR 12.5.0 and Mediator 3.0.2

Measured before Relevox had any code, so the targets are set by what exists rather than by what we hope.

```
BenchmarkDotNet v0.15.8, Windows 11 (10.0.26100.9448/24H2)
Intel Core Ultra 7 255H 2.00GHz, 16 logical and 16 physical cores
.NET SDK 10.0.402, runtime .NET 10.0.13, X64 RyuJIT x86-64-v3, DefaultJob
```

Source: [`benchmarks/Relevox.Benchmarks`](../../benchmarks/Relevox.Benchmarks). Every scenario is checked by
`--sanity` first, so a row cannot quietly skip a behaviour or a listener. Handlers return a cached or
constant result, so the numbers are the cost of getting there.

## What this changes

**Mediator's 1.2 ns is a lifetime decision more than a dispatch one.** Both libraries ran with their
documented defaults. Mediator registers handlers as singletons, so its generated code can hold the handler
instance and the send becomes a direct call with nothing resolved from the container. MediatR registers
handlers as transient and resolves one per call. Neither is configured badly; they made different trade-offs.

That puts the plan's hypothesis "typed send within 10% of Mediator" out of reach for any design that
resolves a handler per call ([ADR 0004](../adr/0004-resolve-per-call.md)): one container lookup costs more
than Mediator's whole call. The hypothesis is rejected as written, before any code exists, which is the
cheapest time to reject it.

What follows for Relevox:

- **Keep per-call resolution as the default** for transient and scoped handlers. Handlers that take a
  `DbContext` are the common case in codebases moving off MediatR, and a singleton default would turn each
  of them into a captive dependency.
- **Cache handlers whose registration is singleton**, decided once at startup from the service
  descriptors. That gives users who can use singletons the same shape Mediator has, without making it the
  default for those who cannot. ADR 0004 is amended to make this part of v1 rather than a later optimisation.
- **Compare like with like.** M4 adds a Mediator build with transient handlers, which needs its own
  assembly because Mediator reads its lifetime option at compile time. Until then, Mediator's numbers here
  are for singletons only.

MediatR's per-call cost here (36 ns, 128 B) is lower than fastcast's earlier measurement (52 ns, 272 B)
because these rows return the library's task directly instead of awaiting it inside an `async` method,
which added a state machine to every row in that run.
