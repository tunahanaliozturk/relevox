# 1.1.0: every benchmark on the release code

Same machine and harness as the earlier results, every benchmark class run on the 1.1.0 code, one class at a
time:

```
BenchmarkDotNet v0.15.8, Windows 11 (10.0.26100.9448/24H2)
Intel Core Ultra 7 255H 2.00GHz, 16 logical and 16 physical cores
.NET SDK 10.0.402, runtime .NET 10.0.13, X64 RyuJIT x86-64-v3, DefaultJob
```

The machine was busier than for [1.0.1](2026-10-20-1.0.1.md): MediatR's own send measured 39.8 ns here against
32.5 ns then, and BenchmarkDotNet called several distributions bimodal. Compare each library with MediatR in the
same table, not absolute numbers across runs.

## What 1.1.0 changed in these numbers

Nothing in the send, publish or stream paths. The changes that touch generated code are registrations, made
once at startup, and diagnostics.

- **Register and send once** allocates 19.5 KB against 17.5 KB in 1.0.1. Which handlers the mediator may hold
  is now worked out when the first mediator is built, from the registrations then in force, which builds the
  lifetime table a second time.
- **Send with three behaviours** came out at 0.55 of MediatR, against 0.47 for 1.0.1. The pipeline path did not
  change, and an A/B run of 1.0.1 and 1.1.0 on this machine, twice each, put them in overlapping ranges:
  1.0.1 at 60.4 and 49.5 ns, 1.1.0 at 55.6 and 69.4 ns, with MediatR between 114 and 134 ns. The allocation,
  392 B, is the same. Read this row as noise until a quieter run says otherwise.
