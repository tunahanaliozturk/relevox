# 1.0.1: every benchmark again, and a regression found

Same machine and harness as the earlier results, every benchmark class run in full on the 1.0.1 code:

```
BenchmarkDotNet v0.15.8, Windows 11 (10.0.26100.9448/24H2)
Intel Core Ultra 7 255H 2.00GHz, 16 logical and 16 physical cores
.NET SDK 10.0.402, runtime .NET 10.0.13, X64 RyuJIT x86-64-v3, DefaultJob
```

## What happened

1.0.1 registers every handler under its interfaces as well as its class, so the send benchmark was run again
to show the send path had not moved. It had moved, but not because of 1.0.1: running the same benchmark on
1.0.0 gave the same slow numbers.

| Send benchmark | M4 (`b79d6b2`) | 1.0.0 | 1.0.1 |
|---|---:|---:|---:|
| Relevox, typed | 9.3 ns | about 20 ns | **7.8 ns** |
| Relevox, `ISender` | 15.7 ns | about 25 ns | **11.3 ns** |
| Relevox singletons, typed | 0.48 ns | about 11 ns | **0.94 ns** |

A `git bisect` on the singleton row put it at the commit that turned the built-in behaviours into slots
(`42f25d2`, PR #8). The first send of a request type works out what its pipeline holds and remembers the
answer. A request with no behaviours at all was remembered as a pipeline, not as direct, so every later send
asked the container for an empty list of behaviours and ran an empty chain. Nothing failed: only the time
went up, by about 10 ns a send, for the most common kind of request there is. The README kept showing the M4
numbers because the slot work re-ran only the pipeline benchmarks, which have behaviours and never take that
path.

The fix is two lines in `PipelineState`, with a test that fails without it
(`A_request_with_no_behaviours_is_sent_directly_after_its_first_send`).

The scale benchmark had broken on its own as well. Its generated source file began with an `<auto-generated/>`
comment, and since `23ef61b` Relevox leaves generated code out the way the compiler's analyzers do, so every
Relevox row failed with no handler found. The file no longer carries the marker, and CI now runs the scale
benchmark's `--sanity` check next to the main one's, so neither problem can come back without a red build.
